Install Forge

Prerequisites

  • Python 3.12 or newer
  • Git
  • An API key from one of the supported providers (DeepSeek, OpenAI, Anthropic, Google, Groq, Mistral, OpenRouter, or Ollama for local models)

Clone and set up

$ git clone https://github.com/Chenboda01/Forge-AI.git $ cd Forge-AI $ python -m venv .venv $ .venv/bin/pip install -e .

Configure providers

Create a .env file with your API keys:

# .env DEEPSEEK_API_KEY=sk-your-deepseek-key OPENAI_API_KEY=sk-your-openai-key ANTHROPIC_API_KEY=sk-your-anthropic-key GEMINI_API_KEY=your-gemini-key OPENROUTER_API_KEY=sk-your-openrouter-key GROQ_API_KEY=gsk-your-groq-key MISTRAL_API_KEY=your-mistral-key

Launch Forge

$ forge

Or select a specific model:

$ forge # Uses FORGE_MODEL or Ollama default

How Forge works

Forge is workflow-first. The model recommends actions — the workflow engine controls permissions, approvals, limits, and recovery.

1

Understand

Forge inspects your project, reads relevant files, and builds context before proposing any change.

2

Plan

A structured plan is created. Subagents can be delegated for read-only exploration and review.

3

Propose

Forge proposes patches. Every destructive action — writes, commands, deletions — requires your approval.

4

Validate

Tests, lint, type checks, and Git diffs provide evidence. Forge never claims success without proof.

Terminal commands

/help Show commands /models List available models /model NAME Switch the active model /status Show provider, model, and workspace /usage Token count and estimated cost /files List project files /read FILE Read a UTF-8 text file /tree Show the project tree /agents List available subagents /agent NAME Delegate a task to a subagent /sessions List saved conversations /new Start a new conversation /compact Reduce context when it grows /updates Check for Forge updates /clear Clear the display /exit Exit Forge

Security by design

  • No automatic fallback. If a model request fails, Forge reports the error. It never silently switches providers.
  • Secrets redacted. Environment variables, API keys, and private key files are not sent to cloud providers.
  • Path containment. Tools cannot read or write outside the project workspace.
  • Approval gating. Write, command, and delete operations require user approval through a trusted modal.
  • Prompt-injection defense. Repository content cannot grant permissions or override configured policies.
  • Execution limits. Step limits, command timeouts, output caps, and delegation depth prevent runaway agents.
